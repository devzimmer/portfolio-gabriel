EngPocket

Site management for civil engineers, run from a WhatsApp chat.

01 — Problem

Civil engineers lose hours to repetitive paperwork: daily site logs, expense entries, building-code lookups, quantity takeoffs. They already live in WhatsApp, so that is where the product had to be.

EngPocket lets them do that work by text, voice or photo, and keeps the records in a web app with projects, finances and monthly reports. I built it with a civil-engineer co-founder, who owns the domain and sales; I own the product and all of the technology.

02 — What I built

A WhatsApp agent with 11 tools

Function calling over OpenAI, with speech-to-text and vision: it writes daily logs from voice notes, books expenses from receipt photos, checks building codes and diagnoses defects from pictures.

A serverless backend

23 Supabase Edge Functions and pg_cron jobs replaced a self-hosted n8n server. Billing runs on webhooks from three checkout platforms.

A multi-agent office In development

Six agents in sequence analyse a client’s files and draft reports. The model reads and writes; prices and calculations stay in code.

04 — Key decisions

  1. A

    Move every automation from n8n into versioned code

    Each function shipped in shadow mode first: it logged what it would do without writing. A flag switched it live, and one update rolled it back. Billing and the bot kept running throughout, and the dedicated server was switched off.

  2. B

    Queue and debounce in Postgres

    Idempotent by message id, with stuck batches reclaimed. The trade-off is a reply that waits at least 7 seconds, in exchange for one coherent answer instead of five fragments.

  3. C

    Keep the WhatsApp gateway behind one module

    Sending and receiving never leaked into the agent, its tools or billing. That boundary is what made the incident below a five-day fix instead of a rewrite.

05 — The incident

5 days

from ban to the official API in production

The bot ran on an unofficial WhatsApp gateway, and the number was banned.

I wrote the migration plan the same day and shipped it in three phases: a signed webhook, sending through the Graph API, then approved templates for messages outside the 24-hour window. The agent, its tools, the queue and billing did not change. The lesson I carry into every project: choose the official API early, and keep external dependencies behind an interface.
